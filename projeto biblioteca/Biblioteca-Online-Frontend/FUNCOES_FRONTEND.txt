GUIA DAS FUNÇÕES DO FRONTEND — BIBLIOTECA ONLINE
Data da inspeção: 16/09/2026

1. COMO LER ESTE DOCUMENTO
==========================
Este guia descreve o código existente no frontend, organizado por arquivo.
Os caminhos abaixo são relativos à pasta Biblioteca-Online-Frontend.
Inclui funções exportadas, funções internas, métodos de classes e callbacks
(funções executadas em resposta a eventos, resultados ou percursos de listas).
Funções das bibliotecas, como useState e fetch, são explicadas no contexto em
que são usadas; não são funções implementadas pelo projeto.

A análise foi feita por leitura do código, sem executar a aplicação ou os
testes. As descrições indicam o comportamento implementado no frontend, sem
confirmar o comportamento de serviços externos ou do backend em execução.

Termos usados:
- Componente: função que devolve uma parte visual da página.
- Hook: função que conecta um componente a estado ou comportamento do React.
- DTO: formato dos dados recebidos ou enviados entre partes do sistema.
- Promise: resultado que ficará disponível depois de uma operação assíncrona.
- Token: credencial recebida no login e enviada nas consultas autenticadas.
- AbortSignal: sinal que permite cancelar uma requisição em andamento.

2. VISÃO GERAL DOS FLUXOS
========================
Login: LoginForm.submit -> criarLogin -> autenticar -> api -> iniciarSessao
-> navegação para /catalogo.

Cadastro: CadastroForm.submit -> criarUsuario -> criarLogin e validadores
-> cadastrarUsuario -> api -> mensagem de sucesso e limpeza do formulário.

Catálogo: Catalogo -> ConsultaLivros -> useConsulta -> buscarLivros -> api
-> apresentação de cartões com Capa.

Detalhe: página /catalogo/[id] -> LivroDetalhe -> useConsulta -> buscarLivro
-> api -> apresentação de informações e links disponíveis.

Usuários: Usuarios -> useConsulta -> listarUsuarios -> api -> tabela.

Sessão: AuthProvider acompanha o armazenamento e useAuth acessa o contexto;
AreaAutenticada controla o acesso visual
e programa a expiração; encerrarSessao apaga a sessão. A autorização das
requisições depende do backend.

4. CAMPOS E VALIDAÇÃO COMPARTILHADA
=================================
Arquivo: src/shared/domain/campos.ts

Função: texto(form, name): string
- Recebe os dados de um formulário e o nome do campo procurado.
- Lê o campo, usa texto vazio se não existir e converte o valor em string.
- Remove espaços do início e do fim com trim().
- Retorna o texto normalizado; não verifica se ele é obrigatório.
- Exemplo: nome="  Ana  " resulta em "Ana".

Função: digitos(value, length, label): string
- Recebe um texto, a quantidade esperada de dígitos e o nome do campo.
- Remove pontos, hífens e caracteres de espaço.
- Exige que o resultado contenha exatamente length dígitos de 0 a 9.
- Em caso de erro, lança uma exceção com a mensagem do campo.
- Retorna a sequência numérica como texto, preservando zeros iniciais.
- Exemplo: digitos("01001-000", 8, "CEP") retorna "01001000".
- Não remove letras ou outros símbolos: rejeita a entrada se eles restarem.
- Não calcula dígitos verificadores de CPF nem verifica a existência de CEP.

Função: obrigatorio(value, label): string
- Verifica se o valor fica vazio depois de remover espaços nas extremidades.
- Se ficar vazio, lança a mensagem "<campo> é obrigatório.".
- Caso contrário, retorna o valor ORIGINAL, sem aplicar trim ao retorno.
- Isso permite validar uma senha sem modificar os espaços digitados nela.

5. COMUNICAÇÃO HTTP
==================
Arquivo: src/shared/http/api.ts

Método: ApiError.constructor(status, message)
- Cria um erro que reúne mensagem e código de resposta HTTP.
- Usa Error como base e guarda status para quem capturar o erro.
- Permite, por exemplo, distinguir uma resposta 401 de outras falhas.

Função: api<T>(path, options = {}, token?): Promise<T>
- É o ponto central das chamadas HTTP do frontend.
- Recebe caminho do endpoint, opções de requisição e token opcional.
- Acrescenta /api antes do caminho: /usuarios vira /api/usuarios.
- Copia os cabeçalhos fornecidos e define Content-Type como application/json
  quando options.body tiver conteúdo.
- Se receber token, adiciona Authorization: Bearer <token>.
- Usa fetch com cache="no-store". Sem method explícito, a chamada usa GET.
- As opções podem incluir body, method e signal para cancelamento.
- Não converte objetos em JSON automaticamente: os serviços fazem isso.
- Se fetch falhar por cancelamento (AbortError), repassa o erro original.
- Para outras falhas do fetch, lança mensagem de conexão com o servidor.
- Para resposta HTTP sem sucesso, tenta ler o JSON e usa body.detail se
  for string. Caso contrário, escolhe uma mensagem conforme o status:
  401: credenciais inválidas ou sessão expirada;
  403: falta de permissão;
  500 ou superior: falha ao concluir a operação;
  demais: pedido para conferir os dados informados.
- Lança ApiError com status e mensagem nessas respostas de erro.
- Em caso de sucesso, retorna o resultado de response.json().
- T descreve o tipo esperado no TypeScript; não valida o JSON em execução.
- Uma resposta de sucesso vazia ou com JSON inválido pode falhar na leitura.

Callback interno: response.json().catch(() => null)
- Se o corpo de uma resposta HTTP de erro não for JSON válido, retorna null.
- Permite preservar o status HTTP e usar uma mensagem padrão.

6. AUTENTICAÇÃO E SESSÃO
=======================
Arquivo: src/modules/autenticacao/dto/login.ts

Função: criarLogin(form): LoginRequest
- Constrói o objeto { cpf, senha } a partir do formulário.
- CPF: aplica texto e digitos, exigindo 11 dígitos após remover a máscara.
- Senha: lê o valor sem trim e verifica apenas se não é vazia/só espaços.
- Preserva exatamente a senha digitada, inclusive espaços nas extremidades.
- Retorna o objeto pronto para envio ou lança erro de validação.
- O mínimo de oito caracteres é validado no cadastro, não nesta função.

Arquivo: src/modules/autenticacao/services/autenticacao-api.ts

Função: autenticar(request)
- Recebe LoginRequest e envia POST /api/auth/login com corpo JSON.
- Não envia token de autenticação.
- Retorna Promise com TokenResponse: accessToken, tokenType e expiresIn.
- Não armazena a sessão; essa responsabilidade é de iniciarSessao.

Arquivo: src/modules/autenticacao/session.ts

Função: read(): Session | null
- Se já existe um valor em cached, devolve esse valor imediatamente.
- Na primeira leitura, procura biblioteca.session no sessionStorage.
- Tenta interpretar o JSON e exige token string, expiresAt numérico e
  expiresAt maior que o horário atual.
- Retorna a sessão válida ou null se os dados faltarem, forem inválidos,
  estiverem expirados ou ocorrer erro de armazenamento/leitura.
- Mantém o resultado em memória para estabilizar as leituras do React.
- A validade temporal não é recalculada quando retorna o cache; a expiração
  ativa é programada por AreaAutenticada.
- A verificação é estrutural e temporal, não uma validação criptográfica JWT.

Função: subscribe(listener)
- Registra uma função interessada em mudanças da sessão no conjunto listeners.
- Retorna uma função de limpeza que remove esse mesmo listener do conjunto.
- É usada por useSyncExternalStore para acompanhar mudanças de estado.

Função interna: publish(session)
- Recebe uma sessão ou null e atualiza cached.
- Se houver sessão, grava JSON no sessionStorage; se for null, remove a chave.
- Se o armazenamento falhar, mantém a atualização apenas em memória.
- Percorre listeners e executa cada função para avisar o React da mudança.
- O callback do forEach chama listener() uma vez por inscrito.

Função: iniciarSessao(response)
- Recebe TokenResponse após o login.
- Usa accessToken como token da sessão.
- Converte expiresIn de segundos para milissegundos e soma ao horário atual.
- Envia { token, expiresAt } para publish.
- Não usa tokenType; a camada HTTP sempre utiliza o esquema Bearer.

Função: encerrarSessao()
- Chama publish(null), limpando a sessão em memória e no armazenamento.
- A notificação faz os componentes reagirem ao logout.
- Não chama um endpoint de revogação do token no backend.

Arquivo: src/modules/autenticacao/context/auth-context.tsx

Componente: AuthProvider({ children })
- Importa read, subscribe, iniciarSessao e encerrarSessao de session.ts.
- Usa useSyncExternalStore(subscribe, read, serverSnapshot) para acompanhar
  o armazenamento. Quando publish chama os listeners, o React relê a sessão.
- Disponibiliza { session, iniciarSessao, encerrarSessao } em AuthContext.
- O callback de useMemo monta esse objeto e mantém sua referência enquanto
  session não muda, evitando notificações de contexto por mera recriação.
- Envolve children com AuthContext.Provider; é usado no layout principal.
- Não duplica a sessão em useState. session.ts continua sendo a fonte dos dados.
- AuthContext é o objeto de contexto criado por createContext, não uma função
  própria. Seu valor padrão undefined identifica a ausência do provider.

Função interna: serverSnapshot()
- Retorna undefined para a leitura da sessão durante a renderização no servidor.
- Representa a sessão ainda não obtida do armazenamento do navegador.

Arquivo: src/modules/autenticacao/hooks/use-auth.ts

Hook: useAuth()
- Lê AuthContext com useContext e retorna sessão e operações de autenticação.
- Lança erro explicativo se for usado fora de AuthProvider.
- Dentro do contexto, session pode ser undefined inicialmente, null sem sessão
  ou um objeto com token e expiresAt quando há sessão.
- O contexto ausente é diferente de session undefined durante a inicialização.
- Substitui o antigo useSessao; componentes não acessam diretamente o armazenamento.

Arquivo: src/modules/autenticacao/components/area-autenticada.tsx

Componente: AreaAutenticada({ children })
- Usa useAuth para obter session e encerrarSessao do contexto.
- Obtém sessão, ferramentas de navegação e caminho da página atual.
- Sem sessão disponível, mostra "Verificando sua sessão…".
- Com sessão, mostra marca, menu Catálogo/Usuários, botão Sair, conteúdo e rodapé.
- Identifica o item ativo do menu verificando o início do caminho atual.
- O botão Sair usa diretamente encerrarSessao.

Callback do useEffect e sua limpeza:
- Quando session é null, troca a rota atual por /login com router.replace.
- Quando há sessão, agenda encerrarSessao para expiresAt menos o horário atual.
- Se o prazo já passou, agenda com atraso zero.
- Retorna uma função que cancela o temporizador ao desmontar o componente
  ou antes de executar novamente o efeito.
- Essa guarda controla a interface; permissões dos dados são do backend.

Arquivo: src/modules/autenticacao/components/login-form.tsx

Componente: LoginForm()
- Usa useAuth para obter iniciarSessao do contexto.
- Mostra campos CPF e senha, mensagem de erro e link para cadastro.
- Mantém error (mensagem) e busy (envio em andamento).
- Desabilita o botão e mostra "Entrando…" durante o envio.

Função interna: submit(event) — assíncrona
- Impede o envio HTML padrão, limpa erros e marca busy=true.
- Extrai FormData, chama criarLogin, aguarda autenticar e inicia a sessão.
- Depois do sucesso, troca a rota por /catalogo.
- Se ocorrer erro, mostra a mensagem dele ou "Não foi possível entrar.".
- Sempre restaura busy=false no finally.

7. CONSULTAS AUTENTICADAS REUTILIZÁVEIS
======================================
Arquivo: src/modules/autenticacao/hooks/use-consulta.ts

Hook: useConsulta<T>(load)
- Usa useAuth para obter session e encerrarSessao do contexto.
- Recebe uma função load(token, signal) que retorna Promise<T>.
- Obtém a sessão e mantém um contador de tentativas e o resultado da consulta.
- Executa a consulta quando sessão, função load ou tentativa mudam.
- Só expõe resultados associados à função load, tentativa e token atuais.
- Retorna { data, error, loading, retry }.
- loading é verdadeiro enquanto não houver resultado correspondente ao
  contexto atual; sem sessão, permanece verdadeiro e nenhuma busca é feita.

Callback do useEffect:
- Se não houver sessão, encerra sem fazer requisição.
- Cria AbortController e chama load com token e sinal de cancelamento.

Callback de sucesso (.then):
- Armazena os dados junto de load, attempt e token.
- Ignora o resultado se a operação tiver sido cancelada.

Callback de falha (.catch):
- Ignora falhas de operações já canceladas.
- Se for ApiError com status 401, chama encerrarSessao.
- Nos demais casos, guarda a mensagem de Error ou uma mensagem genérica.

Callback de limpeza do efeito:
- Chama controller.abort() ao desmontar ou antes de refazer o efeito.
- Evita que uma requisição antiga sobrescreva o estado após a troca de busca.

Função retornada: retry()
- Incrementa attempt para disparar uma nova consulta.
- O atualizador (value) => value + 1 calcula o próximo contador a partir do
  valor anterior. Os dados da tentativa anterior deixam de ser os atuais.

8. CATÁLOGO E LIVROS
===================
Arquivo: src/modules/biblioteca/dto/livro.ts

Método: ConsultaLivros.constructor(termo = "literatura", page = 0)
- Cria o objeto de parâmetros da pesquisa.
- Remove espaços externos do termo e exige que ele não esteja vazio.
- Exige página inteira e maior ou igual a zero; caso contrário, lança erro.
- Guarda termo e page; size é fixado em 12 itens por página.
- As propriedades são readonly no TypeScript.

Método: ConsultaLivros.toSearchParams()
- Retorna uma string de parâmetros de URL contendo termo, page e size.
- Usa URLSearchParams para codificar espaços e caracteres especiais.
- Exemplo: termo=literatura&page=0&size=12.
- Não realiza busca nem altera a consulta.

Função: linkSeguro(value?): string | undefined
- Recebe endereço opcional; se estiver vazio, retorna undefined.
- Tenta interpretar o endereço com new URL(value).
- Aceita apenas protocolos http: e https: e força o protocolo para https:.
- Retorna a URL resultante ou undefined se o endereço/protocolo for inválido.
- Bloqueia, por exemplo, javascript: e data:.
- Não verifica reputação do domínio, existência do recurso ou suporte a HTTPS.
- URLs relativas, sem uma base, não são aceitas por essa implementação.

Arquivo: src/modules/biblioteca/services/biblioteca-api.ts

Função: buscarLivros(consulta, token, signal)
- Converte ConsultaLivros em parâmetros de URL.
- Faz GET /api/livros?termo=...&page=...&size=... usando api.
- Envia token e sinal de cancelamento.
- Retorna Promise<GoogleBooksResponse>, com totalItems e items.

Função: buscarLivro(id, token, signal)
- Codifica id com encodeURIComponent para usá-lo como parte do caminho.
- Faz GET /api/livros/<id codificado> com token e sinal de cancelamento.
- Retorna Promise<Livro> com os detalhes.

Arquivo: src/modules/biblioteca/components/catalogo.tsx

Componente: Catalogo()
- Mantém a consulta atual e uma mensagem de erro da pesquisa.
- Inicia com "literatura", página zero e tamanho 12.
- Usa useConsulta para obter os livros e ConsultaStatus para carga/erros.
- Mostra pesquisa, cartões, termo atual e paginação.
- Trata items nulo/ausente como lista vazia.
- Mostra aviso se não houver resultados na página retornada.
- Cada cartão leva a /catalogo/<id codificado> e apresenta capa, categoria,
  título e autores, com textos alternativos quando faltam informações.
- A página é armazenada a partir de zero, mas exibida ao usuário a partir de 1.
- Desabilita Anterior na primeira página.
- Desabilita Próxima quando vierem menos de 12 itens ou quando a próxima
  posição atingir o total informado. Sem totalItems, usa Infinity nesse cálculo.

Inicializador do useState: () => new ConsultaLivros()
- Cria a consulta inicial quando o estado do componente é inicializado.

Função interna: load(token, signal), criada com useCallback
- Chama buscarLivros com a consulta atual.
- Mantém a referência da função entre renderizações enquanto consulta não muda,
  evitando refazer a consulta apenas por uma nova renderização.

Função interna: search(event)
- Impede o envio HTML padrão e limpa o erro anterior.
- Lê o campo termo e tenta criar uma nova ConsultaLivros.
- Atualiza a pesquisa e reinicia na página zero.
- Se a entrada for inválida, mostra a mensagem e mantém a consulta anterior.

Callback de items.map(livro):
- Converte cada livro em um cartão clicável com Capa e informações resumidas.

Callbacks dos botões Anterior e Próxima:
- Criam outra ConsultaLivros com o mesmo termo e page - 1 ou page + 1.
- Atualizam o estado; a alteração faz useConsulta carregar a página escolhida.

Arquivo: src/modules/biblioteca/components/capa.tsx

Componente: Capa({ livro })
- Escolhe thumbnail ou, se ausente/vazio, smallThumbnail.
- Passa o endereço escolhido por linkSeguro.
- Se houver URL aceita e a imagem não tiver falhado, mostra <img> com
  carregamento adiado (lazy) e texto alternativo baseado no título.
- Caso contrário, mostra uma capa substituta com ícone, título e marca.

Callback onError da imagem: () => setFailed(true)
- Registra uma falha de carregamento e passa a mostrar a capa substituta.
- Não tenta carregar smallThumbnail depois da falha da imagem principal.
- O estado failed não é explicitamente reiniciado quando a propriedade muda.

Arquivo: src/modules/biblioteca/components/livro-detalhe.tsx

Componente: LivroDetalhe({ id })
- Consulta um livro pelo identificador usando useConsulta.
- Mostra link de volta, estado da consulta, capa e informações disponíveis:
  categorias, título, subtítulo, autores, editora, publicação, páginas e idioma.
- Para a descrição, remove trechos parecidos com tags pela expressão
  /<[^>]*>/g e renderiza o resultado como texto, sem inserir HTML diretamente.
- Escolhe webReaderLink ou, se ausente/vazio, previewLink para leitura;
  depois valida o endereço com linkSeguro.
- Se o primeiro endereço estiver preenchido, mas for inválido, não tenta
  automaticamente o segundo após essa validação.
- Mostra links de PDF/EPUB conforme disponibilidade e URL aceita.
- Links externos abrem outra aba com rel="noopener noreferrer".
- Se não houver link de leitura aceito, mostra aviso de indisponibilidade.
- Não hospeda um leitor nem baixa o arquivo por código: fornece os links.

Função interna: load(token, signal), criada com useCallback
- Chama buscarLivro com id, token e signal.
- Só muda de referência quando id muda.

Callback de downloads.map(([label, access]):
- Examina separadamente as opções PDF e EPUB.
- Se isAvailable for verdadeiro, valida downloadLink com linkSeguro.
- Retorna o botão/link correspondente quando há URL aceita, ou null.

9. USUÁRIOS E CADASTRO
=====================
Arquivo: src/modules/usuario/dto/usuario.ts

Função: criarUsuario(form): UsuarioRequest
- Reutiliza criarLogin para obter CPF normalizado e senha preservada.
- Valida a senha com /^.{8,}$/ e lança erro se não corresponder.
  Isso exige pelo menos oito caracteres; o ponto dessa expressão também
  rejeita quebras de linha. Não exige letras, números ou símbolos específicos.
- Normaliza e exige nome e número do endereço.
- Normaliza CEP e exige oito dígitos.
- Normaliza complemento, permitindo texto vazio.
- Retorna { cpf, senha, nome, endereco: { cep, numero, complemento } }.
- Não consulta CEP nem preenche rua/cidade no navegador.

Arquivo: src/modules/usuario/services/usuario-api.ts

Função: cadastrarUsuario(request)
- Envia POST /api/usuarios com UsuarioRequest convertido em JSON.
- Retorna Promise<UsuarioResponse>.
- Não envia token, inclusive quando o cadastro vem da área autenticada.

Função: listarUsuarios(token, signal)
- Faz GET /api/usuarios usando token e sinal de cancelamento.
- Retorna Promise com uma lista de UsuarioResponse.

Arquivo: src/modules/usuario/components/cadastro-form.tsx

Componente: CadastroForm({ interno = false })
- Mostra nome, CPF, senha, CEP, número e complemento.
- Mantém mensagens de erro/sucesso e estado busy durante o envio.
- Usa atributos HTML como required, minLength e maxLength nos campos.
- interno altera títulos, texto do botão e links de retorno/sucesso.
- No modo público, aponta para /login; no interno, para /usuarios.
- Ambos os modos usam a mesma validação e o mesmo serviço de cadastro.
- A tela informa que rua/cidade serão consultadas pelo CEP, mas não há
  função de consulta de CEP neste frontend; isso fica a cargo do backend.

Função interna: submit(event) — assíncrona
- Impede o envio HTML padrão e guarda a referência ao formulário.
- Limpa mensagens anteriores e define busy=true.
- Constrói o pedido com criarUsuario e aguarda cadastrarUsuario.
- Em caso de sucesso, mostra o nome retornado e limpa os campos com reset().
- Não inicia sessão nem redireciona automaticamente após cadastrar.
- Em caso de erro, mostra sua mensagem ou "Não foi possível cadastrar.".
- Sempre restaura busy=false ao terminar.

Arquivo: src/modules/usuario/components/usuarios.tsx

Componente: Usuarios()
- Usa useConsulta(listarUsuarios) para carregar usuários autenticadamente.
- Mostra título, link de novo cadastro e estado da consulta.
- Quando a lista está vazia, apresenta aviso.
- Quando existem usuários, apresenta tabela de nome, CPF e cidade/UF.
- Não implementa edição, exclusão, busca ou paginação de usuários.

Callback de query.data.map(usuario):
- Retorna uma linha da tabela por usuário, identificada por usuario.id.
- Formata CPF com 11 dígitos como 000.000.000-00 usando replace.
- Se o texto não corresponder à expressão, replace o deixa como está.
- Junta localidade e uf com " / ", descartando valores vazios com
  filter(Boolean); na ausência de ambos, mostra "Não informado".
- Boolean é uma função nativa reutilizada, não uma função criada no projeto.

14. LIMITES IMPORTANTES DO COMPORTAMENTO ATUAL
============================================
- CPF é validado pelo formato de 11 dígitos, não pelo cálculo verificador.
- Não há consulta de CEP implementada no frontend.
- O cadastro interno reaproveita o POST público e não acrescenta token.
- Não há distinção de administrador implementada nestas telas.
- linkSeguro restringe protocolos, mas não garante a confiabilidade do site.
- A listagem de usuários não possui edição/exclusão ou paginação.
- O catálogo exibe a proposta de livros gratuitos; este frontend não aplica
  um filtro local de preço/disponibilidade. Ele apresenta o retorno do endpoint.
- Downloads aparecem apenas com isAvailable e downloadLink aceito; não há
  geração ou armazenamento local de PDF/EPUB pelo frontend.
- O tratamento automático de 401 que encerra a sessão está em useConsulta;
  api, isoladamente, apenas lança ApiError.
- Não existe renovação automática de token ou chamada de logout ao backend
  no código inspecionado.
